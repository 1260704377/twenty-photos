# 20张

每天只整理 20 张照片。别急，慢慢来。

这是一个真正访问本地文件的 Electron 桌面应用，无服务器、无账号、无上传。当前版本 **0.1.0**。

## 从 GitHub 下载

前往 [v0.1.0 下载页](https://github.com/1260704377/twenty-photos/releases/tag/v0.1.0)，下载 **`20zhang-v0.1.0-mac-arm64.zip`**，解压后双击 **「20张.app」**。这是已打包的软件，不需要安装开发环境。

`20zhang-v0.1.0-source.zip` 是项目源码，适合继续开发；`SHA256SUMS.txt` 可用于校验下载文件。当前仓库为私有，访问和下载需要仓库权限。

## 直接打开（这台 Mac）

双击项目文件夹里的 **「启动20张.command」**，或打开 **`release/mac-arm64/20张.app`**。

这个安装包针对 Apple Silicon Mac（M1/M2/M3/M4 等）。运行已打包的应用不需要安装 Node.js。也可以把 `20张.app` 拖到“应用程序”文件夹。

若系统询问照片所在目录的访问权限，请允许。首次打开来源于下载的未签名应用时，macOS 可能需要在 Finder 中右键应用 → 打开；本地构建不包含 Apple 公证签名。

## 怎么用

1. 选择一个本地照片文件夹。会包含子文件夹，跳过隐藏内容、符号链接和名为 `20张整理` 的目录。
2. 首页显示待整理数量和找到的照片总数。点击 **开始今天的整理**。
3. 每次只看一张：

   | 操作 | 键盘 | 最终确认后的行为 |
   | --- | --- | --- |
   | 不要了 | ← | 移入 `20张整理/待删除/本次编号/` |
   | 保留 | → | 原文件不变 |
   | 收藏 | ↑ | 移入 `20张整理/收藏/本次编号/` |
   | 稍后决定 | 空格 | 原文件不变，之后的日子可再次出现 |

4. 误点可按 **⌘Z / Ctrl+Z**，或点击“撤销上一步”。按 Esc /“暂时离开”回首页，草稿自动保存。
5. 看完后可以 **查看今天的结果** 并修改选择。只有点击 **确认本次整理** 后，文件才会移动。
6. 今天就到这里。已确认的照片不会重复出现，“稍后决定”除外。
7. 后悔了：在最近一次整理页面点击 **撤销本次整理**，照片恢复原位、统计撤回，重新选择即可。不会覆盖原位置已有的其他文件。

不足 20 张时使用剩余数量；每天 20 张额度在这份本地记录的所有照片文件夹之间共享。当天仍有额度且加入了新照片，可刷新后整理剩余额度；不会自动开启下一轮。所有照片都处理完后会显示完成状态。

## 文件与记录安全

- **没有永久删除功能。**“待删除”仍然是磁盘上的完整照片。
- 操作前先保存可恢复的事务记录；移动目标按批次隔离，使用排他创建并校验 SHA-256 内容。
- 在确认目标副本完整之前，不移除原路径。不会覆盖已存在的不同内容文件。
- 收藏也采用移动，因此不会重复占空间。原照片的内容不被重新编码；缩小后的预览单独放缓存。
- 确认/恢复过程中暂时阻止退出，避免普通误关。意外关闭后，会提示重试或恢复原位。
- 磁盘断开、权限不足或文件被外部改动时停止相应操作并提示。不要在确认或恢复时用其他程序移动/编辑同一批文件。
- 外置磁盘不支持硬链接时采用“排他复制 → 校验 → 移除原路径”。如果复制遇到断电留下不完整目标，程序会保留源文件并停止，需检查目标后重试，不会冒险删除源文件。
- 最多恢复当前照片库最近一批有效整理；恢复后可重新选择。若原文件夹被整体改名，请改回原路径再恢复。
- 本工具是整理工具，不能替代独立备份。不要删除本地记录来“重置”仍在进行的文件操作。

### 本地记录位置

- macOS：`~/Library/Application Support/20张/records.json`
- Windows：`%APPDATA%/20张/records.json`
- `records.json.bak` 保存上一次写入前的备份；正式记录使用临时文件、同步和原子替换写入。记录损坏时会明确报错，不会静默重置记录。事务期间不要直接用旧备份覆盖正式记录。
- 缩略图缓存位于系统缓存目录下的 `20zhang-previews`，可在关闭应用后清理。启动时清理超过约 300 MB 的旧缓存；运行期间按需生成，所以单次长时间浏览可能临时超过这个大小。

累计整理按**确认的选择次数**统计（包含稍后决定；再次处理会再计一次）。连续天数按本机日历、成功确认的日期计算。统计会随撤销回退。“累计待清理空间”是标记待删除照片的大小，**不代表已释放空间**；若你在程序外自行删除/修改整理结果，统计不会自动核实实际磁盘占用。

## 图片支持

- JPG/JPEG、PNG、WebP、GIF（首帧）、TIFF、AVIF、BMP 尽力预览。
- HEIC/HEIF：Mac 使用系统 `sips` 转换兜底；Windows 使用本地 HEIC 解码器。不同编码变体可能不支持，会显示可跳过的错误状态。Windows HEIC 兜底对文件设置了 40 MB 上限。
- 一次解码一张，主线程外生成最长 1800 × 1400 的等比预览，预读下一张；不会同时解码整个照片文件夹。
- 超过 1 亿像素的超大图会限制解码。EXIF 方向由预览器处理，原图不改。
- 拍摄时间来自 EXIF `DateTimeOriginal`，不拿文件修改时间冒充拍摄时间。优先选择历年**同月同日**照片，再按相对路径稳定排序；暂未做“附近几天”的扩展。
- 首次扫描会遍历目录并读取 EXIF（最多 4 路同时读取），大库需要等待。后续使用日期缓存；不做文件系统实时监听，新增照片点“刷新”。

## 开发运行（Mac / Windows）

需要 Node.js 22.12+（建议 24 LTS）及 npm。首次安装依赖需要网络，日常整理不需要网络。

```sh
npm install
npm start
```

或使用锁定版本的 pnpm（项目用 pnpm 11 验证）：

```sh
pnpm install --frozen-lockfile
pnpm start
```

源码无前端构建步骤，没有开发服务器。Windows 请在 Windows 本机安装依赖和打包，使 Sharp 加载匹配平台的图片解码库。

### 测试与打包

```sh
npm test                 # 本地数据及文件安全测试
npm run test:ui          # 启动真实 Electron 窗口并跑完整流程
npm run pack             # 当前平台的应用目录
npm run dist:mac         # Mac ZIP
npm run dist:win         # 在 Windows 本机生成 NSIS 安装程序
```

测试只使用自动生成的独立测试照片。UI 截图、测试记录在 `.test-output/`。Mac 上会用系统编码器生成 HEIC 样本验证真实预览。端到端测试需有可用的桌面会话。

**已实测的平台是这台 Apple Silicon Mac。Windows 源码与打包配置已提供，但尚未在 Windows 真机验证或生成经过验证的 Windows 安装包。**

## 项目结构

```text
src/main/
  main.cjs           Electron 主进程、受限 IPC、本地资源协议、窗口生命周期
  preload.cjs        仅暴露有限操作，不暴露任意文件/系统 API
  library.cjs        扫描、日额度、草稿、持久化、事务移动与恢复
  preview-worker.cjs 独立线程图片解码和缩略图生成
src/renderer/
  index.html         页面入口
  app.js             首页 / 整理 / 结果 / 完成页和快捷键
  style.css          视觉、响应式布局、轻量动画
assets/icon.png      应用图标
scripts/            图标生成、真实窗口测试
 test/              文件安全和状态机测试
```

### 为什么选择 Electron + 原生 JavaScript

本地文件选择和安全移动是核心，需要桌面能力。Electron 同时支持 Mac / Windows，无需配置 Rust 编译链；原生 JavaScript 让这个小项目保持少量模块，没有 UI 框架或打包器负担。代价是安装体积大于 Tauri。

照片操作只在主进程执行；界面开启上下文隔离与沙箱，禁止 Node 集成，检查 IPC 来源，阻止新窗口和外部网络请求。实现参考 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)、[上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation) 和 [自定义资源协议](https://www.electronjs.org/docs/latest/api/protocol)。
